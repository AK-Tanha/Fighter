FIGHTER API - THUNDER CLIENT REQUEST BODY REFERENCE
=====================================================
Base URL: http://localhost:5000/api
(adjust port if different)

Set Body tab to "JSON" in Thunder Client for every POST/PUT request.

BOUT
-------------------------------------------------------
POST   /bouts
GET    /bouts
GET    /bouts/:id
PUT    /bouts/:id
DELETE /bouts/:id
PUT    /bouts/:id/stoppage
GET    /bouts/:id/result

NOTE: red_corner_fighter, blue_corner_fighter, event, referee are IDs (numbers).
judges is an array of IDs. All referenced IDs must already exist
(create Fighters, an Event, and Officials first).

POST /bouts body:
{
  "red_corner_fighter": 1,
  "blue_corner_fighter": 2,
  "event": 1,
  "referee": 1,
  "judges": [1, 2, 3],
  "is_title_fight": true,
  "is_main_event": true,
  "is_co_main_event": false,
  "no_of_rounds": 4,
  "round_time": 180
}

PUT /bouts/:id/stoppage body:
(use this when a bout ends early by KO/TKO instead of going to the judges' scorecards)
{
  "winner": "blue",
  "win_method": "tko",
  "ending_round": 1
}
winner: "red" | "blue"
win_method: "tko" | "ko"
ending_round: the round number the bout ended in

GET /bouts/:id/result
No body needed. Returns the calculated winner:
- If the bout has a recorded stoppage (tko/ko), returns that directly.
- Otherwise, calculates from judges' RoundScore totals:
  winner: "red" | "blue" | "draw"
  method: "decision"
  decisionType: "unanimous" | "split" | "majority" | "majority_draw" | "split_draw"

-------------------------------------------------------
GENERAL RULES
-------------------------------------------------------
1. JSON keys must exactly match what the controller destructures
   from req.body (case-sensitive).
2. Relation fields (anything the controller looks up via
   repo.findOneBy({ id: ... })) must be sent as a plain NUMBER id,
   never a full object, never a string like "1".
3. JSON syntax only - double quotes on all keys and string values,
   no trailing commas, no single quotes, no unquoted keys.
4. Recommended workflow order to satisfy foreign keys:
   Fighter -> Official -> Event -> Bout -> Round -> RoundScore
5. In Thunder Client, use Environment variables to store IDs
   returned from create requests (e.g. {{fighter1_id}}) and reuse
   them in later request bodies instead of copying numbers by hand.
6. A bout that ends by stoppage (KO/TKO) should skip scoring the
   remaining rounds - use PUT /bouts/:id/stoppage instead of
   creating RoundScore records for rounds that never happened.
